# 微信工作桥 0.1.0：本机预览版

更新：2026-11-16。**现在可以试用“手动导入聊天 → WorkBuddy 整理 → 摘要、待办和回复草稿回到桌面”。微信自动读取和自动回复尚未跑通。**

打开 DMG 后，将其中的 `WeChat Work Bridge.app` 拖到个人 Applications 文件夹（`~/Applications`），再打开应用。本次交付机器已经安装并配置 WorkBuddy 的 `wechat_workbench` MCP 服务，无需重复安装。

当前构建面向具备开发环境的 Apple Silicon Mac，依赖系统 Python，经过本机 ad hoc 签名，尚未公证。源码和构建说明保存在 [GitHub 项目的开发分支](https://github.com/left11/WeChat-ChatBot-Mac/tree/codex/probe-270115)，仓库内 `docs/companion.md` 有详细配置及数据保存说明。

## 试一次整理和拟稿

1. 打开“微信工作桥”。可以选择“用示例体验”，或点击“导入聊天”，粘贴一段自己选定的记录；每行可写成“姓名：内容”。导入后会显示来源与原文编号。
2. 选择要处理的消息，在“整理”中点击“复制整理任务”，粘贴到 WorkBuddy 并提交。任务会要求它调用 MCP 保存摘要、待办和原文引用。
3. WorkBuddy 完成后回到工作桥，点击“刷新”。查看摘要与待办，核对不确定事项和对应原文。
4. 在“回复草稿”中点击“复制拟稿任务”，交给 WorkBuddy。完成后刷新，可查看新增草稿，也可自行保存一份草稿。
5. “复制内容”可供手工回发。“确认待发送”只把该草稿记为本地 `ready`，界面仍显示“尚未发送”，不会发到微信。

本次已通过的 WorkBuddy 任务使用合成示例；示例标签会一直保留。若客户端找不到 `wechat_workbench`，到工作桥“连接”页复制当前 MCP 配置，核对 WorkBuddy 的自定义连接器；移动应用后旧绝对路径可能失效。

## 已验证到哪一步

| 项目 | 结果 |
| --- | --- |
| Mac 桌面操作 | 导入、保存摘要/待办、草稿、本地确认待发送与重启后保留数据已验证 |
| 实际 WorkBuddy | 5.5.6 / Hy4 用 1 分 38 秒读取合成会话，保存摘要、3 项待办和未审批草稿；独立数据库读取复核通过 |
| 独立测试 Probe | 微信 4.1.15.35 / build 270115 的 metadata 与 180 秒观察器连接、清理通过，消息样本为 0 条 |
| 私有原生发送实验 | 一条文件传输助手测试文本获得服务端接受；尚无接收端送达证明，未包含在发布功能中 |
| 微信自动读取与回复 | 尚未验证可用，桌面消息通道保持未连接 |

`ready`、服务端接受和接收端送达是不同状态。本版不会用前两者显示“已发送”。日常微信不属于本项目的测试目标。

## 下一版与长期开发

下一步先用已知测试消息证明读取字段、方向和去重，再验证限定测试会话的发送与接收端送达，之后接入桌面适配器及自动回复。WorkBuddy 自动触发也需单独验证，当前仍由用户提交任务。

本地 Mac 负责原生构建和测试账号验收，GitHub 保存源码与 CI，Codex Cloud 可承担编码、合成数据测试和审查；微信进程及账号数据留在本机。项目仓库的 `docs/product.md` 保存产品取舍和推广草案，`docs/competitors.md` 保存竞品资料与来源。
