# 微信工作桥：产品方向与验证

更新：2026-11-16。公开需求与竞品资料获取于 2026-11-15；具体来源见下文和[竞品记录](competitors.md)。

微信工作桥面向用 Mac、经常在微信里接工作的人。产品目标是：**把指定会话中的工作交给 WorkBuddy 处理，保留原文依据，再把结果交回正确会话。** 当前预览版已做到手动导入、WorkBuddy 整理并写回桌面、准备回复草稿；微信自动读取和回发仍在验证。

## 为什么先做这个场景

公开讨论里已经有具体的手工作业和失败经历：

| 观察 | 来源与证据范围 | 对产品的影响 |
| --- | --- | --- |
| 从多个工作群截屏，交给 WorkBuddy 整理事项、责任人、期限，再转进 IMA | [腾讯云社区作者自述](https://developer.cloud.tencent.com/article/2707584)，2026-07-11，带活动推广色彩 | 先验证“原文 → 可跟进的事项”，与现成分享流程比较操作成本 |
| 先把事情发给文件传输助手，之后忘记转到待办 | [TaskCat 创作者自述](https://www.v2ex.com/t/1252480) | 整理结果必须能继续使用，不能只多出一个收藏箱 |
| 微信 AI 工具因记忆串台或容易断连而被停用 | [V2EX 使用讨论](https://www.v2ex.com/t/1242033)，不同评论来自不同用户 | 记录来源、会话归属与失败状态；单次演示不能代替持续使用 |
| 群摘要刷屏，用户希望私聊接收 | [总结鸭作者转述](https://www.v2ex.com/t/1018399)，2024 年历史反馈 | 结果默认留在个人工作台，回传位置和频率由用户选择 |

这些材料支持开展验证，尚不足以估计市场规模或支付意愿。首批目标用户是已有 WorkBuddy 使用习惯、需要整理工作聊天并跟进回复的个人。销售客服、群运营和个人记录的工作方式不同，后续应分别验证。

## 三项能力的主次

| 能力 | 第一版的作用 | 当前状态与下一道验收 |
| --- | --- | --- |
| 聊天整理与待办 | 选定消息，提取进展、负责人、期限和待确认项；每项能回到原文 | 手动导入与本地保存已可用；WorkBuddy 已处理合成会话并写回摘要和 3 项待办。下一步验证真实测试消息的自动读取与引用 |
| 交给 WorkBuddy 执行 | 保留会话和消息范围，让处理结果回到同一工作台 | 实际 MCP 读写已通过；目前仍需把任务粘贴到 WorkBuddy。自动触发及长任务状态还需独立实现和验收 |
| 回复与自动回复 | 先准备可核对的草稿，再逐步支持限定会话、明确触发条件下的自动回复 | 草稿与本地待发送队列已可用；没有发布微信发送适配器。必须先验证接收端送达、重复事件、自发消息和失败恢复 |

首个完整验收场景是一段工作安排：选择消息 → WorkBuddy 整理事项与不确定处 → 查看原文依据和回复草稿 → 核对目标会话 → 回传并在接收端确认。每一步都要有真实状态，`ready` 只表示本地待发送。

暂不把文件处理、跨会话长期记忆和全天群聊值守加入首轮验收。三项能力继续建设，先完成同一项工作的连续处理。

## 形态与工程分工

采用 Mac 桌面伴侣，承载本地消息来源、结果、草稿和待发送状态；DMG 只是安装形式。模型能力先复用 WorkBuddy，避免要求用户另配一套模型。浏览器扩展暂不作为主形态，后续若有明确网页场景再增加。

本机 Mac 负责应用构建、独立测试 Probe 和实机验收。GitHub 保存源码、评审和可重复的离线检查；Codex Cloud 可用于编码、合成数据测试和审查。微信运行、账号数据和原始测试记录保留在本机，Cloud 检查通过不代表微信收发已通过。工程边界见[工程约定](engineering.md)。

## 要证明的差异

WorkBuddy 已有聊天分享和 OpenAPI，第三方也有微信读写接入方案。工作桥需要证明的是：同一任务减少了多少挑选、复制、找回来源和转发操作；安装、维护与核对花费的时间是否抵消这些收益。

首轮试用按一周记录：完成了哪些真实任务、用了几次、与原方法相比省了哪些步骤、草稿修改多少、失败后是否继续使用。若用户只尝鲜一次，或官方分享已足够，应优先调整场景与操作流程。下载量、文章阅读量和 GitHub stars 不作为留存或付费证据。

## 演示与推广草案

先用“WorkBuddy 微信聊天整理”“WorkBuddy MCP 微信”“Mac 微信 AI 助手”覆盖明确的接入需求。项目说明采用第三方身份，公开功能以当前构建为准；“原会话回复”在独立核验送达后再作为能力标题。渠道优先考虑 GitHub 使用说明、开发者社区教程和 V2EX 场景讨论，本轮尚未对外发布推广内容。

三段演示分别承担一个问题：

1. **这段聊天能整理出什么？** 展示导入来源、选中范围、WorkBuddy 实际调用与返回结果；合成数据始终标记为示例。
2. **回复会发给谁？** 展示原文引用、草稿和目标会话。当前版本在“待发送 · 尚未发送”结束，说明仍需手工回发；以后补接收端送达画面。
3. **处理中断怎么办？** 只有断连、恢复和防重复行为通过实测后，再录制对应过程。尚未实现的恢复行为写入已知限制。
