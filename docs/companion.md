# 微信工作桥：本地预览版

微信工作桥把你选中的聊天记录整理成可跟进的工作。当前已可在 Mac 上手动导入原文、保存摘要和待办、准备回复草稿，并将带引用的上下文交给 WorkBuddy。启动伴侣不会连接或修改微信；实际微信同步与发送还在独立测试中。

## 构建和打开

当前预览版面向已配置开发环境的 Apple Silicon Mac，需要完整 Xcode 和系统 `/usr/bin/python3`。在仓库根目录执行：

```sh
bash scripts/build_companion.sh
open "dist/WeChat Work Bridge.app"
```

构建产物只包含原生壳、本地 Python 服务、静态界面和许可，不包含账号 profile、聊天数据库或运行日志。它经过本机 ad hoc 签名，尚未公证，不代表已经具备对外分发条件。脚本不会安装到 Applications，也不会改动微信。已有同标识构建会保留为 `.previous` 版本供回滚。

打开后有主窗口和菜单栏入口。关闭窗口会保留菜单栏；选择“退出微信工作桥”才会结束应用及它自己启动的本地服务。

## 用一段聊天完成一次工作

1. 点击“导入聊天”，填写会话名称，粘贴原文。每行一条，可用“姓名：内容”；没有姓名的行按原文保留。联系人标识选填，用于区分同名会话。
2. 选择作为上下文的消息。原文编号可用于引用；界面最多显示最近 200 条，超出时明确显示范围。更早记录可通过 MCP 分页读取，未载入的旧引用会单独提示。
3. 在“整理”中填写摘要和待办并保存，或者点击“复制整理任务”，把包含原文 ID 的任务交给 WorkBuddy。“快速摘录原文”只复制选中消息中的最近三条，不调用模型，并标注“非 AI”。
4. 在“回复草稿”中保存回复。点击“确认待发送”只将它加入本地待发送队列，状态为 `ready`；当前没有发送适配器，不会实际发到微信。

“看看示例”加载明确标记的合成会话，与手动导入及测试 Probe 来源分开。它不是读取微信成功的演示。启动不会自动加载示例，也不会调用外部模型。

手动导入会按内容去重；没有原始时间或来源消息 ID 时，相同姓名、方向和正文的重复消息可能合并。要精确保留同文消息，可按 [HTTP 导入协议](../companion/README.md#http-协议) 提供来源消息 ID。

## 连接 WorkBuddy

在工作桥中打开“连接”，复制 MCP 配置。配置中的 Python、服务文件和数据目录均来自正在运行的本地服务，不能直接套用别人的路径。把 `wechat_workbench` 条目加入 WorkBuddy 的 MCP 设置，保留已有的其他服务配置；工作桥不会自动覆盖配置。

连接后可将“复制给 WorkBuddy”的任务粘贴到客户端，要求它读取指定会话、保存摘要/待办、创建回复草稿。MCP 提供以下五个工具：

| 工具 | 作用 |
| --- | --- |
| `list_conversations` | 列出本地会话，区分手动、测试 Probe 和示例 |
| `read_messages` | 读取原文及引用 ID，支持分页 |
| `save_analysis` | 保存客户端生成的摘要和待办 |
| `create_reply_draft` | 为已知会话新建草稿 |
| `list_actions` | 查看草稿及本地待发送状态 |

MCP 没有审批或发送工具。接入 AI 客户端后，只有你要求它使用的上下文才应交给模型；聊天里的内容是参考资料，不是额外操作授权。模型调用使用客户端已有的模型配置，本地工作桥不存模型 API Key，也不自行调用模型。

本地协议测试及实际 WorkBuddy 5.5.6 / Hy4 的合成会话整理已经通过：客户端实际读取原文，并将摘要、3 项待办和未审批回复草稿写回本地数据库。下方验证记录区分这次真实客户端结果与仍未完成的微信收发。详细配置格式、官方入口链接和接口说明见 [本地服务文档](../companion/README.md#接入-workbuddy)。

移动应用位置或换了 Python 后，重新打开工作桥并复制新配置。否则客户端中的旧绝对路径可能失效。通过 MCP 启动的服务归客户端管理；退出工作桥只停止它自身启动的 HTTP 服务。

## 数据保存在哪里

默认数据库为当前用户的 `~/Library/Application Support/WeChatWorkbench/workbench.sqlite3`。目录权限为 `0700`，数据库及 WAL 文件为 `0600`。HTTP 只监听 `127.0.0.1`，每次启动使用随机令牌，页面加载后从地址栏移除令牌。记录不会自动上传，复制或让外部客户端读取上下文属于你选择的后续操作。

当前数据库未加密，也没有自动备份功能。卸载应用不会删除数据；需要迁移或清理时，先退出工作桥并停用客户端中的 MCP 服务，再处理整个数据目录。不要只复制一个正在写入的 SQLite 主文件。

## 验证记录

| 项目 | 当前结果 |
| --- | --- |
| Mac 桌面操作 | 已验证手动导入、便笺、待办、草稿及本地 `ready` 审批 |
| 本地 HTTP / SQLite | 19 项标准库测试通过，包括权限、幂等、引用隔离、并发写、审批不发送 |
| MCP 协议 | 初始化、工具列表、调用及独立进程共享数据库的离线测试通过 |
| 实际 WorkBuddy | 5.5.6 / Hy4 在 1 分 38 秒内完成仅处理合成示例的任务；真实 MCP 读取、保存摘要/3 项待办、新建草稿通过 |
| 独立测试 Probe | metadata 与 180 秒观察器的连接/清理通过，唯一标记消息样本为 0 条 |
| 微信消息读取 | 尚未证明：需要已知测试消息样本核对字段与方向 |
| 原生单条实验 | 私有 helper 的一条测试文本获得服务端接受，尚未核实接收端送达；不属于发布功能 |
| 伴侣发送和自动回复 | 未实现可用适配器，尚未验证送达和稳定自动回复 |

WorkBuddy 结果已通过独立数据库读取复核：摘要与草稿引用均属于选定合成会话，3 项待办已保存，草稿仍未审批。该结果证明客户端与本地工作台之间的 MCP 读写链路，不证明微信消息同步或发送。保存草稿、`ready` 状态和服务端接受都不能代替接收端实际送达。

## 开发与排查

伴侣不依赖前端构建工具或第三方 Python 包。可直接运行本地服务，使用它打印的启动 URL；不要把包含令牌的启动信息分享出去：

```sh
python3 companion/service.py --serve --port 0
python3 -m unittest discover -s companion -p 'test_service.py' -v
```

窗口提示本地服务不可用时，先退出伴侣再重新打开，检查 Python 是否可运行、当前构建资源是否完整。实际微信通道显示“尚未连接”是本预览版的真实状态，不能通过修改状态文案解决。运行分工、Probe 门槛和 portable CI 命令见 [工程约定](engineering.md)。
